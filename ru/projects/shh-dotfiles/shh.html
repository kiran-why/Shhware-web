Команды shh

Скрипт: tools/shh в репозитории, после установки — ~/.local/bin/shh. Запускайте от своего пользователя, не от root.

shh config

Меню: какие части системы оставить, а какие убрать. install.sh сам открывает его при первом запуске, пока нет ~/.config/shh/config. Чтобы поменять выбор потом:

shh config

Выбор сохраняется сразу. Изменения установленных файлов и пакетов применяются через shh update (при первой установке — через sh install.sh). Рендерер и устройство рендеринга применяются при следующем запуске Sway из управляемого профиля.

Config и Debloater используют общий интерфейс fzf со строчными ASCII-заголовками и выровненными значениями. В смешанных меню сначала идут пункты выбора и подменю, затем пустая строка и переключатели. Enter открывает пункт или меняет состояние переключателя, Esc возвращает назад.

Файл настроек

Выбор хранится в ~/.config/shh/config, по одной строке NAME=VALUE; его можно править руками. Нет строки — значение по умолчанию. Файла нет в репозитории, поэтому shh update сохраняет ваш выбор.

shh update

 
shh update

Перед применением посмотрите локальный план изменений. Для перехода с copy на link запустите установщик из постоянной копии репозитория.

Обновляет систему и конфиги: запускает install.sh из свежей копии репозитория. Выбор из shh config сохраняется, меню снова не открывается.

  • режим copy: клонирует репозиторий (git clone --depth 1, только последний коммит) во временную папку, запускает оттуда install.sh и удаляет папку, когда он закончит;
  • режим link: git pull --ff-only в репозитории, на который указывают ссылки, потом его install.sh. Обновление остановится, если fast-forward невозможен или Git пришлось бы перезаписать локальные правки.

shh diff · shh update --dry-run

 
shh diff
shh update --dry-run

Команда shh diff показывает изменения файлов, пути будущих резервных копий и настройки клавиатуры, которые будут созданы для Sway. В режиме link правки через установленную ссылку уже находятся в репозитории.

shh update --dry-run также показывает недостающие пакеты и изменения рецептов KISS по локальным данным. Обе команды обходятся без сети, установки и записи dotfiles. Удалённая версия и будущие изменения зависимостей неизвестны. В режиме copy установленный CLI ищет репозиторий в ~/Shh-dotfiles. Если он лежит в другом месте, запустите sh tools/shh diff из его корня.

В предпросмотре обновления выводится remote state unknown. При первой установке итоговый план может изменить меню настроек. У рецептов KISS отображается и смена исполняемости build, даже если содержимое совпадает.

shh doctor

Команда shh doctor показывает справку. При включённом компоненте Shhware Tools выберите одну проверку:

  • shh doctor --config — Проверяет службы, файлы из списка установки, выбранные пакеты, каталог сессии и группы пользователя. Если обязательный список недоступен, выводит UNAVAILABLE и возвращает 1.
  • shh doctor --graphics — Показывает карты DRM, драйверы и разъёмы. Позволяет сравнить запрошенный рендерер с подтверждённым при записанном запуске Sway. Подробнее в разделе о журналах Sway.
  • shh doctor --performance — Показывает нагрузку, RAM, swap и доступные датчики CPU. Два снимка с интервалом около секунды дают процессорное время и RSS процессов рабочего стола. Метка основного цикла Sway показывает время запуска по журналу.
  • shh doctor --build — Проверяет Git, инструменты и рабочую файловую систему без запуска сборки. На KISS показывает свободное место и действующие ограничения параллельных задач make, samu и Cargo.
  • shh doctor --network — Проверяет интерфейсы, состояние Wi-Fi, маршруты основной таблицы и локальные настройки DNS. Внешний IP, разрешение имён и HTTPS остаются NOT TESTED. На вызов локального клиента отводится до двух секунд, общий бюджет — шесть секунд.
  • shh doctor --audio — Проверяет звуковые процессы пользователя, слушателей сокетов, локальный сервер, маршрутизацию и ALSA. Сокет может остаться после остановки сервера. Воспроизведение и физическое подключение остаются NOT TESTED.

Код 0 означает, что показана справка или обязательные проверки не выявили проблем. При этом возможны предупреждения и пробелы в данных. UNKNOWN — данных недостаточно для вывода, UNAVAILABLE — источник недоступен, NOT TESTED — проверка пропущена. Код 1 означает учтённую проблему или ошибку выполнения, 2 — неверные аргументы.

Онлайн-проверки сети

shh doctor --network --online

Обычная проверка сети работает офлайн. Флаг --online добавляет четыре независимые проверки после локального снимка. Оба режима сохраняют сетевые настройки без изменений.

  • ip -4 route get 1.1.1.1 запрашивает у ядра маршрут к IPv4-адресу Cloudflare (2 с). Этот запрос не отправляет пакеты в сеть.
  • ping -n -c 1 1.1.1.1 ожидает один ICMP-ответ до 2 с. Узел или межсетевой экран может отбрасывать ICMP при работающем доступе в интернет.
  • nslookup example.com. запрашивает адрес через настроенный резолвер (3 с). Адрес в ответе подтверждает разрешение имени.
  • curl отправляет HTTPS HEAD на https://example.com/ с учётом переменных окружения прокси. На соединение отводится 3 с, на запрос 5 с, внешний лимит — 6 с. HTTP 2xx даёт OK; другой статус, ошибка прокси или TLS и истечение времени дают WARN.

WARN относится к отдельной проверке и сам по себе не меняет код выхода. Если отсутствует нужная утилита, timeout или setsid, результат — NOT TESTED. Каждый вывод относится только к проверенному адресу, резолверу или ресурсу.

Как читать результаты

Graphics показывает PCI ID, драйверы, разъёмы и прямой доступ к /dev/dri/*. Подключённый экран не определяет GPU рендеринга. requested (this shell) относится к текущей оболочке. Для каждого журнала Sway значение actual выводится, только если запуск подтверждает Pixman или GLES2; actual=unknown означает недостаток данных. Ошибки ищутся в последних 64 КиБ каждого журнала и 256 строках журнала ядра текущей загрузки, до шести совпадений на источник.

Performance показывает среднюю нагрузку, memory PSI при поддержке ядром, имена датчиков и доступные политики частот CPU. Процессорное время рабочего стола — прирост в секундах между снимками. Без --online Network читает локальное состояние без сканирования Wi-Fi и внешних запросов. Отсутствие маршрута по умолчанию в основной таблице не исключает другую маршрутизацию. Audio через wpctl или pactl может показать выходы, устройства по умолчанию и громкость. Список устройств не подтверждает слышимость.

shh report

 
shh report > shh-report.txt

Для сообщения об ошибке можно сохранить локальную сводку. В ней восемь разделов: система, оборудование, конфигурация, графика, производительность, сборка, сеть и звук. Файл создаёт оболочка. Shhware его никуда не отправляет.

Перед отправкой прочитайте файл. Личные пути, сетевые адреса, названия Wi-Fi и исходные строки журналов отфильтровываются, но сочетание оборудования и версий может выдать конкретную машину. Код 0 означает, что отчёт выведен, даже если в одном из разделов есть FAIL.

Отчёт обобщает локальные наблюдения. Внешние запросы и активные проверки звука не выполняются. Наличие процесса не подтверждает ответ сервера, а старая ошибка в журнале не устанавливает причину текущего сбоя.

shh debloater

Debloater входит в Shhware Tools. Он проверяет локальные сведения о пакетах и файлах и находит кандидатов для разбора. Текущая версия выполняет анализ и формирует предварительный план. Файлы и пакеты она не удаляет. Карантина нет.

Запустите shh debloater в терминале с fzf. Отметьте категории, выберите Scan system, затем Review candidates. В карточке указаны причина, размер, известный пакет-владелец и риск. Добавьте нужных кандидатов в Preview plan. Начальный выбор пуст и сохраняется только в текущем сеансе.

  • --scan проверяет пять категорий: пакеты без обратных зависимостей, одноимённые исполняемые файлы, кеши пакетов, остатки сборок и неразрешимые символьные ссылки в ~/.local/bin. Для дубликатов показан приоритет в PATH; копии, ссылки и программы с меньшим приоритетом могут использоваться. В кеше могут находиться архивы для восстановления или активные загрузки.
  • --packages, --duplicates и --cache запускают только соответствующую проверку. За один вызов передаётся один параметр, например shh debloater --packages.
  • В меню дополнительно доступны каталоги кеша Firefox/mpv при отсутствии соответствующего пакета, копии из реестра резервных копий Shhware и файлы от 100 МиБ в Downloads или кеше приложений. Одного размера или возраста недостаточно, чтобы считать файл ненужным.
  • --dry-run запускает стандартный скан, открывает интерактивный выбор и выводит план. Вне терминала сообщает о пустом выборе. --history читает существующую историю очистки; текущая версия не записывает операции. --help выводит список параметров.

На Artix список осиротевших зависимостей предоставляет pacman, на Void — XBPS. Оба менеджера могут показать предварительный состав пакетной операции. Проверка остатков сборок на этих дистрибутивах выводит NOT TESTED. На KISS пакет без обратных зависимостей может быть приложением, которое вы запускаете сами. KISS проверяет рабочее дерево сборки на признаки активной работы. Полный предварительный состав удаления недоступен, поэтому пакетный план блокируется.

Защита учитывает базовые пакеты, инструменты сборки, пакетные списки Shhware, включённые компоненты и защиту пакетного менеджера. Собственные имена пакетов можно указать в ~/.config/shh/config строкой debloater_protected=name1,name2. При неполных данных о защите или неподтверждённом составе операции пакетный план блокируется. Файлы доступны только для просмотра. UNKNOWN означает недостаток данных. Коды выхода: 0 — завершение, 1 — ошибка или неполный скан из командной строки, 2 — неверные аргументы.

shh uninstall

 
shh uninstall
shh uninstall -n

Сначала посмотрите план через shh uninstall -n. Перед удалением сверяются контрольная сумма файла или назначение ссылки из списка установки. Изменённые файлы остаются. Восстанавливаются зарегистрированные резервные копии, а из каталогов удаляются только пустые, созданные установщиком. Старые незарегистрированные копии можно вернуть вручную.

Что остаётся

Пакеты, сервисы, login shell (zsh), группы и системные файлы в /etc* (важно): если откатить их по ошибке, вход сломается (без seatd sway не запустится). shh uninstall печатает их список с командами, чтобы вручную откатить только то, что нужно. Также остаются ~/.config/shh/config и папка репозитория, если вы её оставили.

shh color

 
shh color OLD NEW

Меняет цвет во всех установленных конфигах и скриптах, например shh color d7263d ff0000. Цвет — 6 шестнадцатеричных цифр, # можно не писать, регистр не важен. Палитра перечислена в config/foot/foot.ini.

  • NEW уже где-то используется: предупреждение, с этого момента это один цвет, и меняться они будут вместе;
  • режим copy: следующий shh update вернёт цвета из репозитория (ваши останутся в файлах .bak); режим link: меняются файлы в репозитории.

Чтобы увидеть новый цвет: Super+Shift+C (sway и бар), makoctl reload, новые окна foot и vim / nvim.

shh help

 
shh help

Печатает список команд; shh -h и shh --help делают то же. Без команды или с неизвестной: список и ошибка.
