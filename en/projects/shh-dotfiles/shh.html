Shh commands

The script: tools/shh in the repo, installed as ~/.local/bin/shh. Run it as your user, not root.

shh config

A menu: which parts of the system to keep and which to leave out. install.sh opens it by itself on the first run, while there is no ~/.config/shh/config yet. To change the choices later:

shh config

Changes are saved immediately. Apply changes to installed files and packages with shh update (on the first install, run sh install.sh). Renderer and render device take effect at the next managed Sway startup.

Config and Debloater share an fzf interface with lowercase ASCII headings and aligned values. In mixed menus, choices and submenus come first, then a blank row and the checkboxes. Enter opens a choice or toggles a checkbox; Esc goes back.

The config file

The choices live in ~/.config/shh/config, one NAME=VALUE per line; you can edit it by hand. A missing line = the default. The file is not in the repo, so shh update keeps your choices.

shh update

 
shh update

Before applying changes, inspect the local preview. Switching from copy to link requires running the installer from a persistent checkout.

Updates the system and the configs: runs install.sh from a fresh copy of the repo. Your choices from shh config stay, the menu does not open again.

  • copy mode: clones the repo (git clone --depth 1, only the last commit) into a temporary folder, runs install.sh from it and deletes the folder when it ends;
  • link mode: git pull --ff-only in the repo the links point to, then its install.sh. The update stops if Git cannot fast-forward or would overwrite local edits.

shh diff · shh update --dry-run

 
shh diff
shh update --dry-run

Use shh diff to see which files would change, where a backup would go and what Sway keyboard settings would be generated. In link mode, edits made through an installed link are already in the checkout.

shh update --dry-run also lists missing packages and KISS recipe changes using local data. Neither preview fetches, installs or writes dotfiles. The remote revision and future dependency changes are unknown. In copy mode the installed CLI looks in ~/Shh-dotfiles. For a checkout elsewhere, run sh tools/shh diff from its root.

The update preview reports remote state unknown. On the first install, the configuration menu may change the final plan. KISS recipe changes include the executable bit of build, even when its contents match.

shh doctor

Run shh doctor for help. With Shhware Tools enabled, choose one check:

  • shh doctor --config — Check services, files in the installation manifest, selected packages, runtime directory and login groups. An unreadable required list gives UNAVAILABLE and exit code 1.
  • shh doctor --graphics — Inspect DRM cards, drivers and connectors. Compare the requested renderer with the renderer confirmed in a recorded Sway startup. See Sway logs.
  • shh doctor --performance — Read load, RAM, swap and available CPU sensors. Two process samples about a second apart show desktop CPU time and RSS. The Sway main-loop timestamp measures startup within the log.
  • shh doctor --build — Check Git, build tools and the working filesystem without building. On KISS, inspect free space and the active job limits for make, samu and Cargo.
  • shh doctor --network — Inspect interfaces, Wi-Fi association, main-table routes and local DNS settings. External IP, DNS resolution and HTTPS remain NOT TESTED. Local client queries get up to two seconds each within a shared six-second budget.
  • shh doctor --audio — Check user audio processes, socket listeners, the local server, routing and ALSA. A socket can outlive its server. Playback and physical connections remain NOT TESTED.

Exit code 0 means help was shown or no required check reported a problem. Warnings and gaps in the evidence are possible. UNKNOWN means inconclusive, UNAVAILABLE means the source could not be used, and NOT TESTED marks a skipped probe. Exit code 1 means a counted problem or execution error; 2 means invalid arguments.

Online network checks

shh doctor --network --online

The default network check is offline. Adding --online runs four independent probes after the local snapshot. Neither mode changes network settings.

  • ip -4 route get 1.1.1.1 asks the kernel for the route to Cloudflare’s IPv4 address (2 s). This lookup sends no packet.
  • ping -n -c 1 1.1.1.1 waits up to 2 s for one ICMP reply. A host or firewall can drop ICMP even when internet access works.
  • nslookup example.com. asks the configured resolver for an address (3 s). An address in the answer confirms resolution.
  • curl sends an HTTPS HEAD request to https://example.com/ using its proxy environment. The connection limit is 3 s, the request limit 5 s and the outer timeout 6 s. HTTP 2xx gives OK; other responses, proxy errors, TLS failures and timeouts give WARN.

WARN describes that probe and does not by itself change the exit code. A missing probe tool, timeout or setsid gives NOT TESTED. Each result applies to the tested address, resolver or resource.

Reading the results

Graphics reports PCI IDs, bound drivers, connector status and direct access to /dev/dri/*. A connected display does not identify the rendering GPU. requested (this shell) describes this shell. For each Sway log, actual is shown only when startup evidence confirms Pixman or GLES2; actual=unknown means there is too little evidence. Error matches cover the last 64 KiB of each log and the last 256 lines of the current boot's kernel log, up to six matches per source.

Performance includes load averages, memory PSI when available, sensor names and CPU frequency policies. Desktop CPU time is the increase between samples in seconds. Without --online, Network reads local state without scanning Wi-Fi or contacting external services. A missing default route in the main table does not exclude other routing. Audio checks standard Shhware sockets and can show outputs, default devices and volume through wpctl or pactl. A device listing does not confirm audible playback.

shh report

 
shh report > shh-report.txt

Save a local summary for a bug report. Its eight sections cover the system, hardware, configuration, graphics, performance, build tools, network and audio. The shell creates the file. Shhware does not upload it.

Read the file before sharing. Personal paths, network addresses, Wi-Fi names and raw log lines are filtered, but hardware and version combinations can still identify a machine. Exit code 0 means the report was printed, even if a section says FAIL.

The report summarizes local observations. It makes no external requests and skips active audio probes. A visible process does not prove its server responds, and an old log error does not establish the cause of a current failure.

shh debloater

Part of Shhware Tools, Debloater inspects local package metadata and files for candidates worth reviewing. It analyzes and previews a plan. It never removes packages or files and has no quarantine.

Run shh debloater in a terminal with fzf. Check the categories to include, choose Scan system, then Review candidates. Open a card for the reason, size, known package owner and risk. Add individual candidates to Preview plan. Selection starts empty and lasts only for this session.

  • --scan checks five categories: orphan package candidates, same-name executables, package caches, build leftovers and unresolved symlinks in ~/.local/bin. Duplicate results show PATH precedence; copies, links and shadowed programs can still be useful. Cache entries may be recovery archives or active downloads.
  • --packages, --duplicates and --cache run just the named scan. Pass one option per invocation, for example shh debloater --packages.
  • The menu also offers Firefox/mpv cache directories when the corresponding package is absent, restore copies listed in the Shhware backup ledger, and files of at least 100 MiB under Downloads or the application cache. Age and size alone do not establish that a file is unused.
  • --dry-run opens the default scan for interactive selection and prints the preview. Outside a terminal it reports an empty selection. --history reads existing cleanup history; this version writes no cleanup entries. --help lists the options.

On Artix, pacman identifies orphan dependencies; on Void, XBPS supplies its orphan list. Both can preview the native package transaction. Build leftovers show NOT TESTED on these distributions. On KISS, a leaf package can be an application you use directly. KISS inspects its build tree for possible active work and has no complete native removal preview, so package plans are blocked.

Protection covers base packages, toolchains, Shhware package lists, enabled components and package-manager protection. Add your own package names to debloater_protected=name1,name2 in ~/.config/shh/config. Incomplete protection data or an unverified transaction blocks the package plan. Files are for review only. UNKNOWN marks missing evidence. Exit codes: 0 for completion, 1 for an error or partial command-line scan, 2 for invalid arguments.

shh uninstall

 
shh uninstall
shh uninstall -n

Preview with shh uninstall -n. Removal checks each manifest entry against its saved checksum or link target. Changed files stay in place. Recorded backups can be restored, and only empty directories created by the installer are pruned. Older unrecorded backups remain for manual recovery.

What stays

Packages, services, the login shell (zsh), the groups and the system files in /etc* (important): undoing them by mistake breaks the login (without seatd sway does not start). shh uninstall prints a list of them with the commands to undo by hand only what you need. Also stays: ~/.config/shh/config and the repo folder, if you kept it.

shh color

 
shh color OLD NEW

Changes a color in every installed config and script, e.g. shh color d7263d ff0000. A color is 6 hex digits, # optional, case does not matter. The palette is listed in config/foot/foot.ini.

  • NEW already used too: a warning, from now on both are one color and change together;
  • copy mode: the next shh update puts the repo colors back (yours stay in .bak files); link mode: the repo files change.

To see the new color: Super+Shift+C (sway and the bar), makoctl reload, new foot and vim / nvim windows.

shh help

 
shh help

Prints the list of commands; shh -h and shh --help do the same. With no command or an unknown one: the list and an error.
